# UI/UX Guide

## Direção visual

A interface deve parecer um sistema real de gestão, orçamento técnico e operação diária. A experiência deve ser densa, clara e produtiva, sem visual de landing page.

## Princípios

- Interface operacional antes de estética promocional.
- Densidade moderada, com boa leitura.
- Hierarquia visual objetiva.
- Ações principais sempre visíveis.
- Estados de dados claros: loading, erro, vazio e sucesso.
- Formulários diretos, sem textos de marketing.
- Tabelas e filtros como elementos centrais.
- Responsividade sem perder capacidade operacional.

## Layout base

- Sidebar lateral fixa no desktop.
- Menu superior compacto com contexto da página.
- Área principal de trabalho com largura fluida.
- Breadcrumbs quando a navegação tiver profundidade.
- Conteúdo dividido em blocos funcionais, não em seções promocionais.
- Mobile com navegação recolhida.

## Paleta visual

Usar cores sóbrias e profissionais:

- Fundo principal: cinza muito claro ou quase branco.
- Superfícies: branco ou cinza industrial claro.
- Bordas: cinza neutro.
- Texto primário: grafite.
- Texto secundário: cinza técnico.
- Ação primária: azul petróleo ou azul operacional.
- Sucesso/aprovado: verde contido.
- Atenção/enviado/aguardando: âmbar.
- Erro/recusado: vermelho contido.
- Cancelado/expirado: cinza.

Evitar:

- Gradientes chamativos.
- Blocos decorativos.
- Ilustrações sem função.
- Botões gigantes.
- Hero section.
- Cards promocionais.

## Tipografia

- Fonte sans-serif moderna e legível.
- Títulos compactos.
- Labels claros.
- Tabelas com tamanho de texto eficiente.
- Não usar tipografia hero em telas operacionais.
- Não usar letter spacing negativo.

## Dashboard

O dashboard deve mostrar:

- Cards de indicadores.
- Últimos orçamentos.
- Obras recentes.
- Atalhos rápidos.
- Distribuição por status.
- Valores totais relevantes.

Comportamento:

- Sem slogans.
- Sem textos comerciais.
- Métricas devem ser objetivas.
- Estado vazio deve orientar ação prática.

## Tabelas

Cada tabela deve ter:

- Busca.
- Filtros relevantes.
- Badges de status.
- Ações por linha.
- Estado vazio.
- Estado de carregamento.
- Erro amigável.
- Paginação quando necessário.

## Formulários

Formulários devem:

- Agrupar campos por assunto.
- Exibir validação por campo.
- Ter botão salvar claro.
- Ter feedback de salvando.
- Evitar campos longos sem necessidade.
- Preferir página ou drawer/modal conforme complexidade.

## Status visuais

Orçamentos:

- Rascunho: cinza.
- Enviado: azul.
- Aprovado: verde.
- Recusado: vermelho.
- Expirado: âmbar/cinza.
- Cancelado: cinza escuro.

Projetos:

- Planejamento: cinza.
- Em orçamento: azul.
- Aguardando aprovação: âmbar.
- Aprovado: verde.
- Em execução: azul escuro.
- Finalizado: verde contido.
- Cancelado: vermelho/cinza.

## Orçamentos

A tela de orçamento deve priorizar:

- Cliente e obra no topo.
- Status e número visíveis.
- Itens em tabela editável.
- Totais sempre fáceis de conferir.
- Campos comerciais em área própria.
- Observações internas separadas das observações do cliente.
- Ação de gerar PDF clara.

## Acessibilidade básica

- Contraste adequado.
- Foco visível.
- Labels associados a inputs.
- Botões com nomes compreensíveis.
- Ícones com tooltip ou texto quando necessário.
- Não depender apenas de cor para status.

## Responsividade

- Desktop: sidebar fixa e tabelas amplas.
- Tablet: sidebar compacta ou recolhível.
- Mobile: navegação em menu, formulários em uma coluna e tabelas roláveis/compactas.
- Nenhum texto deve sobrepor botões ou cards.

## O que não fazer

- Não criar landing page.
- Não criar página de vendas.
- Não criar hero promocional.
- Não usar blocos de marketing.
- Não usar animações excessivas.
- Não criar cards decorativos sem função.
- Não deixar a tela vazia demais.
- Não misturar instruções de uso longas dentro da interface.
